# 10 — Draw appearance sync: the story owns the draw moment

**Legacy:** was #38 in the love-letter effort.

**What to build:** a draw currently *visually completes* the instant its event folds — the card lands in the drawer's hand, the deck count drops, the seat hand count bumps — while the previous card action's scene is still animating (~4.6s). At the physical table (and in the engine's event order — `resolvePrinceChoice` emits `cardDiscarded` before `cardDrawn`; `finishTurn` emits the next player's draw only after the previous resolution) the draw happens *after* the action. Make the appearance match the story: a draw that lands while the scene queue is busy is **held** — the drawer's own card, the deck count, and the seat hand counts keep their pre-draw values — and **released** when the story reaches it (the queue drains), at which moment the card appears, the deck drops, the count bumps, and the ticket 7 pop fires as the draw's narration. The round-boundary instance (the next round's deal landing mid-story) is already fixed by ticket 9 (the round can only start after the story drains) — this ticket is the mid-round, every-turn case.

**Architecture (grilling Q4 — A+D):** a single-source presentation seam, `useStory`, replaces the ad-hoc gates that have been accumulating (`busy`, `currentEntry`, `lastDraw`, `deckPulse`) with one hook that owns the queue, the story position, the lagged display view, and the release logic. Game.tsx renders story-related display (hand, deck count, seat counts) **only** from the lagged view. Draws become log entries (D), so the seam derives everything from the log — one input, three outputs (scenes, held draws, released draws) — and the `lastDraw` packet plumbing dies.

**Blocked by:** none (ticket 9 is independent and uses the same seam's shape)

**Status:** ready-for-agent

- [ ] **D — draws in the log:** core `LogKind` gains `'draw'`; `view.ts`'s `cardDrawn` logs `log('draw', { playerId, shrunk, name? })` — `name` (the drawn card's identity) only on the drawer's own stream (privacy, same as peek); `shrunk: false` for the burned-card draw (ruling 4 — the deck count does not shrink). Not `cardDealt`/`turnStarted` — deals and turn markers are never held and would only add noise. `formatLogEntry` renders draw lines ("B 抽了一张牌"; the drawer sees the card name), localized en + zh through the typed dictionaries (ADR-0004)
- [ ] **The seam — `story.ts`:** `storyFor` = the existing `scenesFor` + a draw ledger; emits `{ scenes, held, released }`. Held = draws whose log id is beyond the story position (the head beat's entry id; newest id when idle); released = draws the story has passed. Cancellation edge ①: a `discard` (countess) for a player with a held draw whose `name` matches the discarded card → the held draw is cancelled (the drawn card was discarded in the same burst; releasing it would show a card that is gone and underflow the hand count)
- [ ] **The hook — `useStory`:** owns the queue + story position + `lagView` (hand minus held self cards, `deckCount + held.shrunk` count, per-player hand counts minus held); release happens when the queue drains (position → newest id); `busy`/`currentEntry` keep the ticket 5 shape. Edge ② — burned-card draw: `shrunk: false` means the deck display is not inflated
- [ ] **Game.tsx:** hand, deck count (top bar + center table), and seat hand counts render from the lagged view only; the ticket 7 pop fires on the *self draw release* and keys on the drawn card's identity (name, not rank — the current rank-based pop highlights every matching duplicate), so it becomes the draw's narration with no stale echo; the deck pulse moves to the lagged deck count (fires at release, not at fold). Edge ③ — two draws in one burst (a Prince'd target's draw + the next turn's draw): both hold, both release together at drain; the target's draw appearing at drain (not after its discard fly) is accepted for now — mid-scene release is a later refinement, noted
- [ ] **Edge cases verified:** ① forced-Countess collision, ② burned-card draw, ③ two draws in one burst, ④ reduced motion (queue never busy → draws always instant) and reconnect (mount baseline skips history → instant)
- [ ] **Tests:** `story.test.ts` (mirrors `scenes.test.ts`) — held/release ordering, the countess cancellation, the burned draw, two-draw bursts, reduced-motion/reconnect immediacy; ui-smoke — a mid-round draw is invisible to the drawer's dock and the deck count until the scene drains, then appears (drawer face-up; other tabs see the deck count + hand count move at the same moment); no error banners
- [ ] core + typecheck + smoke + ui-smoke green

## Comments

**Symptom (from to-discuss.md):** "The card actions still plays, but the card supplement has already been done" — clarified by the reporter: the card animations are still going on, and the next round starts and sends the draw for the player in turn. The round-boundary half is ticket 9; this ticket is the same pattern mid-round (every turn, the next player's draw lands while the previous play's scene animates).

**Decisions (grilling session — Q2, Q4, Q5, 2025):**
- **Q2** — appearance sync (B): hold the drawn card + deck count + seat counts until the story reaches the draw; the pop fires at release. Rejected the state-first alternative (draws visibly complete early — the reported bug) and hiding only cosmetic beats. The card appearing at release coincides with `busy` clearing, so the drawer can act exactly when they can see their hand.
- **Q4** — architecture (A+D): one `useStory` seam with a lagged display view; Game renders only from it; draws enter the log. Rejected the story-cursor rewrite (dual-view reducer + packet buffer + a silent head/queue lockstep invariant — too expensive for this project) and server-side beats (against ADR-0007).
- **Q5** — draw lines display (A): the strip and log modal show draw entries; the log stays a complete transcript (ADR-0003); filter later if noisy.
- **Trade-offs accepted:** the seat hand-count bump is a bump-and-drop at the release moment (the drawer can play as soon as `busy` clears) — opponents may miss that the drawer held 2 cards; the deck count dropping in sync is the public "someone drew" narration (the same signal as the physical deck shrinking), and the drawer's own pop marks their card. Deck/hand numbers can briefly disagree between viewers (each client lags its own story); display-only, self-heals at release.

**Current state (facts for the implementer):** draws are *not* in the log today — `view.ts`'s `cardDrawn` mutates `deckCount`/`handCount`/hand without a `log(...)` call, so `scenesFor` never sees them; the ticket 7 pop is fed by a `lastDraw` reducer field (self only) + a Game effect gated on `scenes.busy` (fires late — a stale echo); the deck pulse fires on every `view.deckCount` change, ungated. `usePlayScenes` (PlayScenes.tsx) is the current seam to extend. The engine and the event stream stay untouched (ADR-0007).
